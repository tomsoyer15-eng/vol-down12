# trend2 — независимая реализация симулятора трендовой стратегии

Вторая, независимая реализация. Выведена из словесного описания задания и
раздела 21 протокола `ADD-PROTOKOL-SVOD-red13-18-08-2026.pdf`.
Существующая реализация не просматривалась — в этом смысл упражнения.

## Состав

- `konfig.py` — пути, постоянные и все разрешённые неоднозначности одним местом;
- `zagruzka.py` — сбор исходных данных в кеш `kesh/dannye.pkl`;
- `podgotovka.py` — панели: сигнал, колебания, пол, связь, даты роллов;
- `dvizhok.py` — симуляция счёта;
- `metriki.py` — итоговые меры;
- `zapusk.py` — основной прогон, второй прогон и шесть самопроверок задания;
- `proverki.py` — проверки самого движка (реконструкция, зонд достижимости);
- `vsjo.py` — всё подряд, от данных до отчёта;
- `audit_dannyh.py` — инвентаризация данных;
- `VOPROSY.md` — список вопросов к заданию, `vyvod/` — результаты.

Запуск: `python3 vsjo.py` (около 25 секунд).

## Разрешение неоднозначностей

Все спорные места вынесены в `VOPROSY.md` и разрешены ответами заказчика; в коде
они собраны в `konfig.NASTROJKI`, так что смена прочтения — это правка одной
строки и повторный прогон, а не переписывание.

Существенные для сверки решения (взяты по ответам заказчика, не по моему умолчанию):
сигнал считается по НЕскорректированной склейке; позиция ставится на закрытии
последнего торгового дня месяца и действует весь следующий месяц; пересчёт
размера месячный; n в формуле размера — число рынков С ДАННЫМИ, а не в позиции;
капитал делится пополам между частями ежемесячно; потолок номинала 300% капитала
части; пол на оценку колебаний — 10-й процентиль собственной прошлой истории;
ES и ZN торгуются полными контрактами; микроверсии в широкой ноге у пяти рынков
(GC /10, SI /5, HSI /5, FDAX /5, SNK /40).

## Что установлено при аудите данных (18.08.2026)

1. **Из 64 рынков таблицы роллирования данных нет по семи**: LLG, CGB, FGBL,
   FGBM, FGBS, YXT, YYT. Выгрузки 2/3/4 их не содержат. ES и ZN взяты из
   `data/norgate/full_history.pkl` репозитория (ES с 1997-09-09, ZN с 1982-05-03).
2. **Поконтрактных файлов в выгрузках нет.** Они есть только для ES, ZN и GC
   (в pkl репозитория).
3. **Правило раздела 21 проверено на золоте** — единственном рынке, где есть и
   колонка `delivery_month`, и поконтрактные файлы. Правило «переложиться в
   первый торговый день, когда до последних торгов остаётся не более N
   календарных дней» при N=28 воспроизводит фактические даты смены
   `delivery_month` с медианой расхождения 0 дней и стандартным отклонением
   3.08 дня — таблица раздела 21 обещает для этой группы разброс 3.0.
   Следствие: даты смены `delivery_month` можно брать как даты ролла напрямую.
4. **Склейка Norgate — разностная (аддитивная)**: `backadj − unadj` равно нулю на
   последнем контракте и постоянно внутри контракта. Значит дневной результат
   одного контракта = `Δ(backadj) × множитель`. У 24 рынков скорректированный
   ряд в какой-то момент уходит в минус, поэтому доли и отношения к
   скорректированной цене недопустимы; номинал считается по нескорректированной.
5. **Валюты**: 8 в наличных данных (AUD, EUR, GBP, HKD, JPY, KRW, SGD, USD),
   девятая (CAD) появится вместе с CGB. Курсы AUD/CAD/GBP/JPY/EUR/CHF/MXN/NZD
   строятся из валютных фьючерсов как `цена × множитель / истинный размер
   контракта`; у иены множитель Norgate занижен в 100 раз (6J котируется 0.6365
   при истинном курсе 0.006365). Для HKD, KRW и SGD источника нет.
6. **Ставка**: DTB3 (трёхмесячный вексель США) из `r33build/data/dtb3.csv`,
   1954–2026, без пропусков после протяжки.
