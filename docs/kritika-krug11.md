# Рецензия одиннадцатого круга ред. 33 (gpt-5.6-sol, pro)

1. **Критический — неверная позиция / ложный триггер капа. `live/feed.py`, `closing_values()`**  
   После получения и проверки `spy_t` функция всё равно возвращает:
   ```python
   return es_to_unit(es_t), dref, None, ...
   ```
   То есть нога А замыкается по `ES/10`, а не по SPY. Фьючерсный базис до разрешённых 2% непосредственно попадает в `prev_close_lev`: кап 2,00 может быть ложно включён либо пропущен, и следующая сессия удержит неверное число ES/MES. Комментарий «замыкание по SPY» не соответствует исполняемому коду.

2. **Критический — ложное доказательство исправления №1. `live/invariants.py`, `_r6()`**  
   Проверка «плечо закрытия ПО SPY» сравнивает полное `r['lev']`, включающее ногу Б, с двумя величинами, содержащими только вклад ноги А:
   ```python
   lev_spy = (...) / 1_000_000
   lev_es = (...) / 1_000_000
   return abs(r['lev'] - lev_spy) < abs(r['lev'] - lev_es)
   ```
   Положительный вклад ZN делает полное плечо выше обоих кандидатов, поэтому тест обычно выбирает просто больший из SPY и ES/10. Он проходит даже при фактическом использовании ES/10 — именно это сейчас и происходит.

3. **Критический — поставка после длительного простоя. `live/daily.py`, `missed_roll_check()` / `roll_passed_for()`**  
   Навёрстывание работает лишь пока дата остаётся внутри месяца ролла:
   ```python
   ft = first_tag(m.date)
   b.ser_* == ft
   ```
   После пропущенного августовского ролла книга держит `U26`, но в сентябре `first_tag()` уже возвращает `Z26`; одновременно `roll_passed_for()` вне августа всегда возвращает `False`. Значит запуск после простоя до сентября не переносит U26→Z26, а только получает поздний отказ `delivery_risk` уже в месяце поставки. Денежный путь — удержание ES/MES/ZN в поставочной зоне и остановка автоматики вместо немедленного ролла.

4. **Высокий — переход на Е не доходит до автопилота. `transition.py`, `hand_over_book()`; `live/autopilot.sh`, `route()`**  
   Автопилот считает источником маршрута `~/.addfut/route.txt`, но `hand_over_book()` этот файл вообще не пишет. После F→E новый `book-E.json` существует, однако автопилот при отсутствии/старом файле продолжает вызывать `session.py --route F`. Сверка с брокером остановит торговлю и замыкание, книга Е останется `close_provisional=True`, следующая сессия также будет запрещена. Утверждение в комментарии `route.txt # действующий маршрут пишет hand_over_book` ложно.

5. **Высокий — маршрут Е использует календарь CME вместо европейских бирж. `live/autopilot.sh`, `is_trade_day()`; `live/feed.py`, `build_market(route='E')`**  
   И автопилот, и точная предыдущая сессия CSPX/CBU0 основаны на `HOLIDAYS_CME`. На американский праздник при открытых LSE/EBS маршрут Е вообще не торгует; на европейский праздник при открытой CME он запускается и получает отсутствующий/неверно датированный бар с тревогой. Денежный путь — пропущенный обязательный ребаланс или аварийная остановка действующей ETF-книги на несколько дней.

6. **Высокий — реестр ролла обновляется не там, откуда его читает торговля. `live/first_connect.py`, `main()`**  
   Читатели поддерживают `ADDFUT_REGISTRY`, но генератор безусловно пишет:
   ```python
   out = ROOT / 'live' / 'instruments_live.csv'
   ```
   При настроенном внешнем реестре программа сообщает успешное обновление, а `feed.py` и `IBBroker` продолжают читать старый файл из `ADDFUT_REGISTRY`. На ролле новая серия отсутствует или старый `con_id` остаётся активным: перенос остановится после закрытия старой серии либо вообще не начнётся. Это ещё и ложный аудиторский след «реестр записан».

7. **Высокий — заявленный API-handshake шлюза обходится на обычном пути. `live/autopilot.sh`, `ensure_gw()`**  
   Если TCP-порт 4002 открыт, функция немедленно возвращает успех:
   ```bash
   if exec 3<>/dev/tcp/...; then ...; return 0; fi
   ```
   Проверка `managedAccounts()` выполняется только после попытки запуска шлюза. Полуживой Gateway с открытым сокетом допускается к торговому запуску вопреки комментарию «ПОРТ — НЕ РУКОПОЖАТИЕ». Итог — тайм-аут сессии, ALARM и пропущенная позиция/ролл; счётчик `gw-fails` при этом сбрасывается.

8. **Высокий — маршрут Е не замыкается в объявленное окно. `live/autopilot.sh`, `tick()`**  
   `close_after()` определяет для Е `1040`, но нигде не используется. Реальное условие жёстко зашито:
   ```bash
   if [ "$hm" -ge 1605 ] ...
   ```
   Книга Е остаётся предварительно незамкнутой ещё 5+ часов после европейского закрытия. Если машина или Gateway недоступны вечером, замыкание теряется, а следующая торговая сессия блокируется из-за `close_provisional`. Комментарий об окнах по маршруту является ложным доказательством.

9. **Высокий — переход может продать источник и затем подать нулевую покупку. `transition.py`, `_run_lots()`**  
   После продажи всегда вызывается:
   ```python
   want = max(0, int(round(unp[leg] / dprice)))
   broker.buy_units(dst, want)
   ```
   При остатке меньше половины зерна цели `want == 0`. Стенды `_TrBroker` и `_B` молча принимают нулевую заявку, поэтому дефект скрыт; реальный адаптер обычно её отвергнет. Источник к этому моменту уже продан, `fail()` зафиксирует MIXED, а книга останется непарной до ручного восстановления — прямой рыночный риск перехода.

10. **Средний — сайдкар уровней может сам легализовать новый источник. `live/signal_update.py`, `_verify_levels()` / `_update_locked()`**  
    `_verify_levels()` не только проверяет, но сразу атомарно перезаписывает `signals_levels.csv` — до проверки битового перекрытия второй ноги и до публикации основного ряда. При первом запуске, удалённом сайдкаре или сбое позже в цикле текущие уровни поставщика становятся новой базой доверия, хотя обновление сигнала завершилось отказом. Повторный запуск уже сравнивает источник с ним самим. Неоднородный пересчёт, сохранивший старые биты, может затем перевернуть пограничный новый месяц и открыть/закрыть целую ногу без обнаружения. Заявление «уровни сверяются с записанными» не доказывает происхождение первой записи и атомарность пары файлов.
