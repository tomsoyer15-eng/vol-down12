# Рецензия пятнадцатого круга ред. 33 (gpt-5.6-sol, pro)

1. **КРИТИЧНО — неверная позиция ноги Б: `live/daily.py`, `step()`**  
   `d_fix` меняется при любом переключении сигнала Б:
   ```python
   if roll_b or bd_switch:
       b = replace(b, d_fix=m.dref_prev)
   ```
   Это прямо противоречит заявленному исправлению «`d_fix` — только роллом ноги Б». При выключении и последующем включении Б модельная единица ZN пересчитывается без ролла, меняя число контрактов и границы полосы. Денежный путь: ложная единица ZN → лишний/недостающий контракт → неверная экспозиция и P&L.  
   **Ложное доказательство:** `sim_v164.sim164()` содержит ту же ошибку (`if roll_today or bd_switch`), поэтому `replay_check.py` доказывает лишь совпадение двух одинаково неверных реализаций с прежним правилом.

2. **ВЫСОКО — починка пер-ножного ролла оставила глобальное списание издержек: `live/daily.py`, `step()`**  
   При просрочке только одной ноги выставляются `roll_a`/`roll_b` раздельно, но стоимость определяется общим `roll_any`:
   ```python
   if roll_any:
       e -= S.ROLL_BP * (exp_e + exp_b)
   ```
   То же заложено в `e_after()` кап-аллокатора. Если просрочена только Б, код списывает ролл также с исправной ноги А; при просрочке только А — с Б. Денежный путь: фиктивное уменьшение капитала → неверная цель и кап-коррекция → недобор контрактов, особенно на границе округления.  
   **Ложное доказательство:** сценарий `смешанная книга: просрочена только Б` в `invariants.py` проверяет только конечные серии, но не `capital_after_costs`, плечо и отсутствие списания по исправной ноге.

3. **ВЫСОКО — автопилот не распознаёт заявленный штатный повтор: `live/autopilot.sh`, `run_trade()`**  
   `session.py::main()` возвращает для `Refused` код **2**, а автопилот требует код **1**:
   ```bash
   elif [ $rc -eq 1 ] && echo "$out" | grep -q 'не новее'
   ```
   Если Python успел сохранить книгу, но процесс умер до `touch traded-$day`, следующий тик получает законный отказ «сессия не новее», однако ставит `ALARM-trade-*`. Денежный путь: автопилот останавливается, последующие роллы/сигнальные сокращения не исполняются; старая серия может остаться до поставочной зоны.  
   Это также опровергает заявление «штатность исхода определяется фразой плюс кодом возврата»: проверяется невозможная для этого исхода комбинация.

4. **ВЫСОКО — аварийные функции автопилота возвращают успех: `live/autopilot.sh`, `run_trade()` и `run_close()`**  
   После создания `ALARM-*` последней выполняется успешная `log`, поэтому функция возвращает 0:
   ```bash
   echo "$out" > "$ST/ALARM-..."
   log "ТРЕВОГА ..."
   ```
   Ручные `autopilot.sh trade` и `close`, а также внешний надзор получают успешный код процесса после неудачной торговли или замыкания. Денежный путь: вызывающий оркестратор считает операцию завершённой и может продолжить переход/отчётность при незамкнутом плече либо несостоявшейся сделке.  
   **Ложное доказательство:** комментарий обещает «фраза ПЛЮС код возврата», но код возврата уничтожается самой функцией.

5. **СРЕДНЕ-ВЫСОКО — неполный сайдкар уровней отключает проверку источника: `live/signal_update.py`, `_check_levels()`**  
   Существование файла считается достаточным. Если в нём нет столбца нужной ноги или нет общих месяцев, функция молча разрешает обновление:
   ```python
   if sym not in df.columns:
       return
   ...
   if not common:
       return
   ```
   Повреждённый `signals_levels.csv` только с SPY переводит IEF обратно на слабую проверку 12 битов. Денежный путь: неоднородно пересчитанная история IEF может сохранить старые 12 знаков, но изменить свежий знак → включить или выключить десятки ZN на месяц.  
   **Ложное доказательство:** тест проверяет лишь полное отсутствие сайдкара; частичный или не пересекающийся сайдкар не моделируется.

6. **СРЕДНЕ-ВЫСОКО — пустой ISIN в реестре означает “проверка не нужна”: `live/contracts.py`, `verify_isin()`**  
   ```python
   want = (row.get('isin') or '').strip()
   if not want or c.conId in _ISIN_OK:
       return []
   ```
   Для строки `sec_type=STK` с пустым ISIN торговля продолжается, хотя заявлено, что пустой ISIN — отказ. Проверки тикера, валюты и площадки недостаточно для нескольких листинговых линий одного фонда. Денежный путь: подменённый/усечённый реестр направляет CSPX или CBU0 в другую линию с иной валютой, налоговым режимом или ликвидностью. `first_connect.py` генерирует полный реестр, но торговый контур обязан защищаться и от повреждения уже опубликованного файла.

7. **СРЕДНЕ — закрытие считается защищённым резервной копией, хотя отказ копирования не останавливает контур: `live/autopilot.sh`, `run_close()` и `backup_state()`**  
   Сначала создаётся `closed-$day`, затем вызывается копирование. При ошибке `tar`, `mv` или `backup_push.sh` создаётся только строка лога; `ALARM` не ставится, код успеха сохраняется, повтор закрытия блокируется отметкой:
   ```bash
   touch "$ST/closed-$day"
   backup_state "$day"
   ```
   `backup_push.sh` вообще вызывается без проверки результата. Денежный путь: после следующей порчи `book-*.json` или намерения восстановиться не из чего, хотя автопилот уже зафиксировал успешное замыкание. Это ложное доказательство наличия послезамыкательной резервной точки.
