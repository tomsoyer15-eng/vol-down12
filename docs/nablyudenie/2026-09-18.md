## 2. ОТКЛОНЕНИЕ: токен Google Drive снова отозван — до остановки контура 3 замыкания

**Факт, измеренный живой пробой в этой сессии (только чтение):**
```
~/bin/rclone lsd vol-down12-drive:
-> CRITICAL: ... couldn't fetch token: invalid_grant: maybe token expired?
```

**Когда умер.** Граница снята разбором `~/.addfut/wip-push.log` по сериям:
```
ok     с 2026-08-19 16:10:20 по 2026-09-05 18:07:05  (599 записей)
ОТКАЗ  с 2026-09-05 18:37:01 по 2026-09-10 08:37:01  (221 записей)
ok     с 2026-09-10 19:37:14 по 2026-09-17 19:07:06  (341 записей)
ОТКАЗ  с 2026-09-17 19:37:01 по 2026-09-18 08:37:01  (27 записей)   <- идёт сейчас
```
Токен прожил ровно **7 суток**: переавторизация 10.09 вечером -> смерть 17.09 между 19:07 и
19:37. Это подпись известного ограничения — OAuth-приложение rclone в статусе Google
«Testing», где refresh-токен протухает каждые 7 дней (PROJECT-STATE §0в п.4, BACKLOG 22б).
Предыдущий цикл был такой же: 05.09 -> 10.09. Файл `~/.config/rclone/rclone.conf` изменён
17.09 18:35 — это последняя удачная выгрузка обновила токен, и он умер в течение часа.

**Почему это срок, а не просто шум.** Отказ drive-плеча делает `backup_push.sh` ненулевым
(`_rc=1`, tools/backup_push.sh — правка 27.08, находка №11), а автопилот считает отказы
подряд и на третьем останавливается (tools/autopilot.sh:1407-1415):
```
log "внешняя выгрузка копий не удалась ($pf подряд)"
if [ "$pf" -ge 3 ]; then
    alarm_write "$ST/ALARM-push.txt" "backup_push.sh не удаётся $pf замыканий подряд — внешних копий нет"
    log "ТРЕВОГА: внешние копии не выгружаются — автопилот остановлен"
```

**Счётчик сейчас 0** (`~/.addfut/push-fails` не существует — замыкание 17.09 в 18:36 ещё
успело выгрузиться: `drive ok`). Отсюда расчёт по торговым дням:

| замыкание | что будет | `push-fails` |
|---|---|---|
| 18.09 пт 18:35 | drive ОШИБКА | 1 |
| 21.09 пн 18:35 | drive ОШИБКА | 2 |
| **22.09 вт 18:35** | **ALARM-push -> автопилот остановлен** | **3** |

То есть сессия **23.09 не состоится**, если токен не восстановить **до вечера вторника
22.09**. Выходные счётчик не двигают — замыканий в них нет.

**Лечение — только в браузере заказчика:** `~/bin/rclone config reconnect vol-down12-drive:`.
Безголового пути нет: сервер Google отвергает обновление по refresh-токену, а `reconnect`
требует живого входа в аккаунт. Проверено опытом в этой сессии (проба выше), а не
предположением; сам сделать не могу — это живая авторизация в браузере (правило 13).

**КАРТОЧКИ ДЕФЕКТА НЕТ, И ВОТ ПОЧЕМУ.** Классов A–F здесь не возникает:
* позиция, заявки и торговая арифметика не затронуты — плечо drive лежит в слое копий;
* остановка контура на третьем отказе **предусмотрена нормативом** (пятнадцатый круг, №7):
  это штатный fail-closed «внешних копий давно нет — стоим до ручного разбора», а не
  необоснованная остановка класса D;
* локальные точки восстановления свежие, git-зеркало и GitHub работают (см. §4).
Остаётся **ограничение версии, уже записанное в BACKLOG 22б**, которое по расписанию
повторяется раз в неделю. Production-код не трогаю: правило «BACKLOG не трогается до конца
пилота» и режим пилота §1. Требуется действие заказчика, а не правка.
